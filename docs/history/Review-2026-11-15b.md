# Review 2026-11-15, second: the dock tools' common list

The points from the common list of mwc's dock tools (deskControl, digitalClock,
osDisplay, pulseControl) that also apply to mfm, as pulseControl read them on main at
0e09085. pulseControl 443bf65 is the reference for the common forms.

## Status

All points settled on fix/dock-common. A test that fails without its fix was checked by
taking each fix out in turn and running the suite. Points without a test say why.

## Theme

1. **`rgb:` still took `0x`.** The first review only required a hex digit first, and
   the 0 of `rgb:0xf` is one. Now mwc's form: `strspn` over the hex digits. Test:
   `rgb:-1`, `rgb:-f`, `rgb: f` and `rgb:0xf` give the default.
2. **`rc_get` was not mwc's `config_get`:**
   - Without `XDG_CONFIG_HOME` and `HOME` it read `/.config/...`; now no file.
   - Lines are read whole with `getline`.
   - The last line wins, even a bad one, and a value too long to keep counts as none.
     The first review had kept the value before it instead.
   Tests: a setting line of 1100 blanks counts; `#ff0000` followed by a value too long
   gives the default. No test for the path: the test box has no writable `/.config`.
3. **`Mwm*foreground` and `Mwm*activeForeground` were not read.** They are now, from
   mfmrc or mwmrc, else black or white by WCAG. Test with pixel counts.
4. **Dimmed text had 4.38:1 on the default background.** `dimmed()` takes the first
   of the dock tools' steps with 4.5:1: 3d3e44 on aeb2c3. The error colour follows the
   background, light on a dark one. Tests with pixel counts at a tolerance of 6.
5. Trough at 0.12: already the same.

## Cursor

6. **The old theme went while its buffer was still on the cursor surface.** The new
   theme is loaded first and shown, or the surface emptied, before the old one goes.
   Tests from the protocol log, with the pointer on the window and on mwc's title bar.
7. **A failed load was never tried again**, as the scale was noted before it. Now only
   on success. No test: it needs a theme that fails to load and then works.
8. **A scale that does not divide the image made the cursor larger.** With
   wp_viewporter the buffer is shown at its size over the scale; without, at the
   largest divisor, noted in CAVEATS. Test: 30 at scale 4 gives a destination of 8 8,
   24 at scale 2 none.
9. **`XCURSOR_SIZE` went through `atoi`, and size times scale could overflow.** A whole
   number only, at most 256. Tests: `32x` gives the default, `1000000000` the largest.

## Wayland

10. **The keymap was read up to a NUL** the protocol does not promise: now
    `xkb_keymap_new_from_buffer` with `strnlen`.
11. **`wl_compositor` was bound below version 4**, which lacks `damage_buffer`. Not
    taken now; the message names version 4.
12. **Seat:** pointer and keyboard are released from wl_seat 3 on, destroyed before;
    a seat that goes is let go of, so the next one is taken.
13. **The wheel waited for `wl_pointer.frame`**, which seats before version 5 never
    send: there each axis event counts by itself. Steps per frame are capped at 20.
    Text cut at a fixed length (the status line, the worker's report and what mfm
    keeps of it) no longer ends inside a UTF-8 character.

No test for 10 to 13: vinput and mwc offer no old seat or compositor, no keymap
without a NUL and no seat that goes; the cut shows only in pixels.

## Command line

As decided for the dock tools: only `-h` given alone prints the usage, on stdout, with
status 0. `--help`, any other argument starting with `-` and a second argument are
refused, the usage on stderr, status 1. A file named `-name` is given as `./-name`.
Test in ui.sh.
